# Интервальные повторения

[English](srs.md) | **Русский** | [Polski](srs.pl.md)

SRS определяет, какую карточку показать и когда вернуть её после ответа. Web и desktop используют один движок FSRS-5; хранилища читают данные и записывают результат в транзакции.

В этом документе слово «карточка» означает одну запись колоды. У неё одно расписание независимо от предмета, направления перевода или показа через картинку.

## Как выбирается интервал

Ядро `fsrs.js` хранит стабильность памяти и сложность вспоминания. Стабильность показывает время в днях, через которое вероятность вспомнить снижается до 90%. Сложность находится в диапазоне от 1 до 10 и относится к памяти пользователя, а не к отметке «сложная задача» в предметной карточке.

Ответ обновляет память с учётом прошедшего времени. Повторение раньше срока, вовремя и с опозданием может дать разные интервалы. Здесь нет одного постоянного множителя для всех ответов.

Параметр `desiredRetention` задаёт целевую вероятность вспомнить. По умолчанию это 0.9, допустимы значения от 0.70 до 0.97. Более высокая цель обычно означает более частые повторения.

Для новой карточки при настройках по умолчанию:

| Оценка | Следующее повторение |
| --- | --- |
| Again | Через 10 минут, шаг обучения |
| Hard | Через 1 день |
| Good | Через 3 дня |
| Easy | Через 16 дней |

Ориентировочная последовательность Good при своевременных ответах: 3, 11, 35, 101, 269 дней. Это пример, а не гарантированное расписание: настройки, время ответа и разброс дат влияют на результат.

## Настройки и дополнительные правила

- `maximumIntervalDays` ограничивает самый длинный интервал. По умолчанию 365 дней. Вариант интерфейса «без ограничения» использует большой технический предел, 36 500 дней.
- `learningSteps` задаёт шаги обучения в минутах. Наступившие шаги обучения и переучивания не блокируются дневными лимитами.
- Again на изученной карточке увеличивает число забываний и запускает relearning. По умолчанию шаг составляет 10 минут; настройка раннего повтора забытых сокращает его до минуты.
- Для одного состояния Hard не позже Good, а Good не позже Easy. На максимальном интервале значения могут совпасть.
- Небольшой разброс дат распределяет карточки по дням. Он детерминирован по записи и числу ответов, поэтому превью кнопки совпадает с записанным результатом.
- Старинные параметры `easyBonus` и `lapsePenalty` читаются для совместимости, но больше не задают расписание.

Изменение настроек не пересчитывает все уже назначенные сроки. Новые параметры применяются при следующей оценке. Кнопка рекомендованных настроек меняет настройки, но не переносит существующие due dates.

## Очередь

Движок берёт наступившие learning/relearning, затем самые старые наступившие review, затем новые карточки. Перемешивание относится к новым карточкам; оно не меняет интервалы.

`newCardsPerDay` и `maxReviewsPerDay` считаются по уникальным записям выбранной колоды за локальный календарный день. Ноль является допустимым лимитом. Дневная цель служит ориентиром, а число всех ответов учитывается отдельно в `answersToday`.

Дополнительная сессия временно снимает дневные лимиты, но не берёт карточки с будущим сроком. Когда доступных карточек нет, она заканчивается. Свободный просмотр всей колоды не меняет расписание.

Пустая очередь различает отсутствие карточек, дневной лимит, ожидание шага обучения и отсутствие наступивших повторений. В снимке есть ближайший срок. UI обновляет очередь по таймеру, при смене дня, возвращении фокуса, обновлении обмена и смене аккаунта.

Готовая очередь не сохраняется в sessionStorage как самостоятельный источник истины. При возвращении данные проверяются заново. Фоновое обновление не должно каждый раз скрывать карточку индикатором построения очереди.

## Запись ответа

1. UI блокирует повторное нажатие до следующего render.
2. Репозиторий сверяет текущий профиль и revision расписания.
3. В одной транзакции записываются новое состояние и review log.
4. Только после успешного сохранения UI переходит дальше.

Устаревший ответ не должен перезаписывать более новое состояние. Ошибка записи оставляет пользователя на текущей карточке. Ответ от предыдущей колоды или закрытой страницы не подменяет новую сессию.

## Старые данные и синхронизация

Даты карточек прежнего SM-2 сохраняются. Если нет памяти FSRS, она выводится из прежнего интервала и ease при следующем ответе через `memoryFromSm2`. Поля `intervalDays` и `easeFactor` остаются для совместимости и статистики.

SQLite хранит `stability`, `difficulty` и время ответа; IndexedDB хранит соответствующие поля объекта. Журнал синхронизации передаёт состояние в `payload.nextCard`. Старое событие без памяти FSRS принимается, а память выводится при следующем ответе. Сервер не пересчитывает интервалы.

## Код и проверки

| Путь | Назначение |
| --- | --- |
| `packages/shared/src/core/usecases/srs/fsrs.js` | Модель FSRS-5 |
| `packages/shared/src/core/usecases/srs/srsScheduler.js` | Шаги, пределы, разброс, превью и revision |
| `packages/shared/src/core/usecases/srs/srsSession.js` | Очередь и лимиты |
| `electron/db/services/srs.services.js` | Запись в SQLite |
| `packages/shared/src/platform/web/model/createWebSrsRepository.js` | Запись в IndexedDB |
| `src/widgets/LearnFlashcardsPanel/model/useSrsSession.js` | Сессия UI, таймеры и защита от гонок |

Формулы сверяются тестами с `ts-fsrs` на 2000 случайных случаев с допуском меньше `1e-6`. Unit-тесты покрывают очередь и миграцию, проверки SQLite транзакции и сохранение, web-тесты используют fake-indexeddb. Это не полная проверка реального одновременного обмена устройств.

Основные команды: `pnpm test:run`, `pnpm check:srs`, `pnpm check:persistence`. Для изменения UI дополнительно нужен [контрольный прогон](smoke-checklist.ru.md). [Настройка окружения](onboarding.ru.md).
