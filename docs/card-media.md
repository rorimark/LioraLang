# Изображения в карточках

## Модель

Изображение — это тип содержимого, а не язык. У записи слова есть текст (слово, перевод) и может быть изображение:

```
word
  source, target, tertiary   — текст на языках колоды
  image: { assetId, alt }    — ссылка на ассет и описание для скринридеров, или null
```

`assetId` — SHA-256 байтов изображения. Одинаковая картинка хранится один раз, сколько бы слов, колод и устройств её ни использовали, и никогда не конфликтует при синхронизации: имя и есть содержимое.

Одна запись слова — одна SRS-карточка (`review_cards.word_id` уникален). Направление решает только, что показать на лицевой стороне и что на обороте, поэтому «картинка → слово» и «слово → картинка» — это способы показать ту же запись, а не новые карточки. Расписание FSRS не меняется.

Код: `packages/shared/src/core/usecases/cardContent/`

- `CONTENT_TYPES` (`text`, `image`), `CARD_DIRECTIONS`, `CARD_PRESENTATIONS` — стороны карточки для каждого направления;
- `resolveCardFaces(word, direction)` — что на лицевой стороне, на обороте и под ответом;
- `resolveCardDirection` — слово без изображения в «картиночном» направлении показывается текстом, слово → перевод;
- `mediaBytes.js` — проверка формата по сигнатуре байтов (JPEG, PNG, WebP, GIF; SVG не принимается), base64;
- `wordSuggestion.js` — форма подсказки для будущего AI-обогащения. Подсказанное изображение приходит уже сохранённым ассетом, не URL.

## Добавление

`@features/word-image-field` — поле «Изображение» в редакторе колоды и в быстром добавлении: выбрать файл, перетащить, вставить из буфера; превью, «Заменить», «Убрать», описание (alt).

`@shared/lib/media/prepareImage.js` перерисовывает картинку: длинная сторона до 1280 px, WebP (JPEG там, где браузер не пишет WebP), ~450 КБ максимум, плюс миниатюра 320 px. Перерисовка убирает метаданные файла (камера, геолокация). Вход до 25 МБ.

## Хранение

| | Web | Desktop |
| --- | --- | --- |
| Байты | IndexedDB, стор `mediaAssets` (ArrayBuffer) | SQLite, таблица `media_assets` (BLOB) |
| Ссылка слова | поле `image` записи слова | колонка `words.image_json` |
| Показ | `blob:` URL (`useMediaImageUrl`) | то же, байты через IPC `media:*` |

Изображение, на которое больше никто не ссылается, удаляется через сутки после последнего касания — не раньше, чтобы картинка, выбранная в ещё не сохранённой форме, не пропала.

Хеш содержимого колоды учитывает изображение только у слов, где оно есть, поэтому у колод без изображений хеш не изменился и лишней синхронизации не было.

## Экспорт и импорт

Формат `lioralang.deck` версии 1 не менялся. Добавлены необязательные поля:

```json
{
  "words": [{ "source": "asparagus", "target": "szparag", "image": { "assetId": "…", "alt": "…" } }],
  "media": [{ "id": "…", "mimeType": "image/webp", "width": 1280, "height": 960, "byteSize": 24000, "data": "<base64>" }]
}
```

Старые файлы без изображений импортируются как раньше; старая версия приложения прочитает новый файл без картинок. При импорте формат проверяется по байтам, размер ограничен 3 МБ на изображение, а ассет сохраняется под хешем, который приложение считает само. Если объявленный `id` не совпадает, ссылки слов переназначаются.

## Синхронизация

Пакет колоды в аккаунте несёт только ссылки (`includeMedia: false`). Байты — отдельные объекты в том же приватном bucket `user-library-decks`, путь `{userId}/media/{sha256}`: миграция не нужна, RLS по папке пользователя уже покрывает их.

- **Push:** изображения колоды загружаются до пакета, который на них ссылается. Загруженные запоминаются в `uploadedMediaIds` профиля синхронизации.
- **Pull:** после колод скачиваются недостающие изображения, до 150 за прогон. Каждое проверяется: SHA-256 должен совпасть с именем. Не скачавшееся остаётся отсутствующим, слово показывает заглушку «Изображения ещё нет на этом устройстве», следующий прогон пробует снова.
- **Конфликты** решаются на уровне колоды, как и раньше. Замена и удаление изображения — это правка слова.
- Сиротские объекты в хранилище аккаунта пока не удаляются.

Код: `packages/shared/src/sync/mediaSync.js`, `createSupabaseSyncApi.uploadMediaAsset / downloadMediaAsset`.

## Проверки

- `pnpm check:media` — сквозная проверка на настоящем SQLite: сохранение, экспорт, импорт с чужим id, старый файл, отказ SVG и чужих байтов, сборка мусора.
- Юнит-тесты: `cardContent`, `deckPackageMedia`, `webMedia`, `mediaSync`, `sha256`, `prepareImage`, `wordSuggestion`.
