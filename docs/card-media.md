# Изображения в карточках

## Модель

У колоды две стороны. Каждая — либо текст на языке (английский, польский…), либо изображение. Изображение — отдельный тип содержимого, а не язык: в списке языков его нет, его выбирают переключателем «Язык / Изображение» у стороны. Картинкой может быть любая сторона, но не обе:

```
deck
  pictureSide: "" | "source" | "target"   — какая сторона изображения
  sourceLanguage, targetLanguage          — языки текстовых сторон; у стороны-картинки пусто
word
  source, target, tertiary                — текст
  image: { assetId, alt }                 — картинка стороны-картинки и её описание для скринридеров
```

В колоде «Изображение → Польский» у слова вместо `source` картинка (`source` может быть пустым). В колоде «Английский → Изображение» — вместо перевода.

`assetId` — SHA-256 байтов изображения. Одинаковая картинка хранится один раз, сколько бы слов, колод и устройств её ни использовали, и никогда не конфликтует при синхронизации: имя и есть содержимое.

Одна запись слова — одна SRS-карточка (`review_cards.word_id` уникален). Направления те же, что у любой колоды: «сторона 1 → сторона 2», обратно и вперемешку. В колоде-картинках это и есть «картинка → слово» и «слово → картинка», без новых карточек. Расписание FSRS не меняется.

Код: `packages/shared/src/core/usecases/cardContent/`

- `CONTENT_TYPES` (`text`, `image`), `PICTURE_SIDES`, `normalizePictureSide`, `CARD_DIRECTIONS`;
- `resolveCardFaces(word, direction, deck)` — что на лицевой стороне и на обороте;
- `hasWordContent` — слово есть, если есть текст первой стороны или картинка;
- `mediaBytes.js` — проверка формата по сигнатуре байтов (JPEG, PNG, WebP, GIF; SVG не принимается), base64;
- `wordSuggestion.js` — форма подсказки для будущего AI-обогащения. Подсказанное изображение приходит уже сохранённым ассетом, не URL.

Хеш содержимого колоды учитывает `pictureSide` и картинки только там, где они есть, поэтому у обычных колод хеш не изменился.

## Интерфейс

- Настройки колоды: у каждой стороны переключатель «Язык / Изображение»; при «Изображении» список языков скрыт.
- Форма слова и быстрое добавление: на стороне-картинке вместо текстового поля — поле изображения (`@features/word-image-field`): выбрать файл, перетащить, вставить из буфера; превью, «Заменить», «Убрать», описание. Вставка списком для колод-картинок скрыта.
- Таблицы слов: колонка стороны-картинки называется «Изображение», в ячейке миниатюра и описание.
- Learn: подписи сторон «Изображение» / язык; картинка вписывается в карточку.
- Hub: колоду со стороной-картинкой пока нельзя опубликовать — у таблицы `hub_decks` нет поля для этого, нужна миграция. Приложение показывает понятное сообщение.

`@shared/lib/media/prepareImage.js` перерисовывает картинку: длинная сторона до 1280 px, WebP (JPEG там, где браузер не пишет WebP), ~450 КБ максимум, плюс миниатюра 320 px. Перерисовка убирает метаданные файла (камера, геолокация). Вход до 25 МБ.

## Хранение

| | Web | Desktop |
| --- | --- | --- |
| Байты | IndexedDB, стор `mediaAssets` (ArrayBuffer) | SQLite, таблица `media_assets` (BLOB) |
| Ссылка слова | поле `image` записи слова | колонка `words.image_json` |
| Показ | `blob:` URL (`useMediaImageUrl`) | то же, байты через IPC `media:*` |

Изображение, на которое больше никто не ссылается, удаляется через сутки после последнего касания — не раньше, чтобы картинка, выбранная в ещё не сохранённой форме, не пропала.

## Экспорт и импорт

Формат `lioralang.deck` версии 1 не менялся. Добавлены необязательные поля:

```json
{
  "deck": { "name": "Kitchen", "sourceLanguage": "", "targetLanguage": "Polish", "pictureSide": "source" },
  "words": [{ "source": "", "target": "szparag", "image": { "assetId": "…", "alt": "…" } }],
  "media": [{ "id": "…", "mimeType": "image/webp", "width": 1280, "height": 960, "byteSize": 24000, "data": "<base64>" }]
}
```

Старые файлы импортируются как раньше. При импорте формат проверяется по байтам, размер ограничен 3 МБ на изображение, а ассет сохраняется под хешем, который приложение считает само; если объявленный `id` не совпадает, ссылки слов переназначаются.

## Синхронизация

Пакет колоды в аккаунте несёт `pictureSide` и ссылки на картинки (`includeMedia: false`). Байты — отдельные объекты в том же приватном bucket `user-library-decks`, путь `{userId}/media/{sha256}`: миграция не нужна, RLS по папке пользователя уже покрывает их.

- **Push:** один раз за прогон читается список объектов в хранилище аккаунта; недостающие картинки колоды загружаются до пакета, который на них ссылается. Если объект когда-то удалили, он загрузится снова.
- **Pull:** после колод скачиваются недостающие картинки, до 150 за прогон. Каждая проверяется: SHA-256 должен совпасть с именем. Не скачавшаяся показывается заглушкой «Изображения ещё нет на этом устройстве», следующий прогон пробует снова.
- **Уборка:** раз в сутки из аккаунта удаляются картинки старше 7 дней, на которые не ссылается ни одна локальная колода и ни один последний пакет колоды в аккаунте. Пакеты читаются, только если есть кандидаты; ошибка уборки не ломает синхронизацию.
- **Конфликты** решаются на уровне колоды, как и раньше. Замена и удаление картинки — правка слова.

Код: `packages/shared/src/sync/mediaSync.js`, `createSupabaseSyncApi` (`listMediaAssets`, `uploadMediaAsset`, `downloadMediaAsset`, `deleteMediaAssets`).

## Проверки

- `pnpm check:media` — сквозная проверка на настоящем SQLite: сохранение, колода-картинки, экспорт, импорт с чужим id, старый файл, отказ SVG и чужих байтов, сборка мусора.
- Юнит-тесты: `cardContent`, `deckPackageMedia`, `webMedia`, `mediaSync`, `sha256`, `prepareImage`, `wordSuggestion`.
- `mediaSync.integration.test.js` — два устройства по очереди на одном аккаунте: колода-картинки приходит на второе устройство, лишняя картинка потом убирается из аккаунта.
